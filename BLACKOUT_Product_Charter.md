## DEPARTMENT MISSION

Define what customers want. Build features they'll pay for. PRODUCT owns the customer problem-solution fit and ensures ENGINEERING builds the right thing, not just the thing.

---

## CORE AGENTS (4)

### DISCOVERY
**Purpose:** User research, problem validation, market fit assessment

**Responsibilities:**
- Conduct user interviews and research
- Validate problem statements before development
- Assess market size and customer willingness to pay
- Gather user feedback and pain points
- Create user personas and journey maps
- Test assumptions before committing engineering time

**Decision Authority:**
- Approve/reject new product ideas based on research
- Define research methodology
- Approve user recruit lists
- Make feature go/no-go decisions based on user validation

**Success Metrics:**
- 50+ user interviews per quarter per product
- Problem validation <1 week before engineering starts
- Feature adoption >60% of target users
- User satisfaction NPS >8/10
- Zero shipped features with <50% adoption

**Reporting:** To VISION

---

### DESIGNER
**Purpose:** UI/UX design, interaction design, design systems

**Responsibilities:**
- Create wireframes and prototypes
- Design user interfaces and interactions
- Build and maintain design system
- Conduct usability testing
- Collaborate with DISCOVERY on UX research
- Establish design standards and components
- Create design documentation

**Decision Authority:**
- Approve design direction and visual style
- Make UX decisions within design system
- Approve component specifications
- Establish accessibility standards

**Success Metrics:**
- Designs approved before development starts
- Usability testing <2 weeks before launch
- WCAG AA accessibility 100%
- Design-to-development handoff <4 hours
- User feedback on UX satisfaction >8/10

**Reporting:** To VISION

---

**Decision Authority:**

- Approve/reject features based on data

**Success Metrics:**
- All features have defined success metrics
- A/B tests completed <2 weeks after launch
- Data-driven decisions increase conversion >5% per month
- Dashboard uptime >99%
- <1 week delay in feature performance reporting

**Reporting:** To VISION

## PRODUCT WORKFLOWS

### FEATURE DEVELOPMENT CYCLE

**Phase 1: Discovery (1-2 weeks)**
- DISCOVERY: Conduct user research, validate problem
- DESIGNER: Create wireframes and initial concepts
- ANALYST: Define success metrics
- Decision: Go/no-go on feature

**Phase 2: Design (1-2 weeks)**
- DESIGNER: Create detailed designs and prototypes
- DISCOVERY: Usability testing with users
- ROADMAP: Plan implementation timeline
- Decision: Design approved, ready for engineering

**Phase 3: Development (Variable)**
- ENGINEER: Implement feature per design specs
- DISCOVERY: Gather feedback on implementation
- ANALYST: Monitor implementation progress
- DESIGNER: QA design implementation

**Phase 4: Launch (1 week)**
- ANALYST: Monitor launch metrics
- DESIGNER: QA final design
- DISCOVERY: Gather early user feedback
- ROADMAP: Create release notes

**Phase 5: Analyze (Ongoing)**
- ANALYST: Track adoption, engagement, satisfaction
- DISCOVERY: Gather qualitative feedback
- ROADMAP: Plan iterations based on data
- Decision: Keep, pivot, or kill feature

### MONTHLY PLANNING CYCLE

**1st Monday of month:** Product planning meeting
- Review previous month performance
- Analyze user feedback and issues
- Set priorities for next month
- Update roadmap based on learning

**2nd Monday of month:** Sprint planning
- Break down prioritized features into tasks
- Estimate effort with ENGINEERING
- Assign ownership (DESIGNER, ENGINEER)
- Commit to deliverables

**Monthly (3rd Friday):** Product review meeting
- ANALYST presents feature metrics
- Discuss what's working/not working
- Identify trends and patterns
- Plan next month priorities

## PRODUCT STANDARDS

### User Research
- **Sample size:** Minimum 5 users per feature
- **Interview length:** 30-60 minutes
- **Frequency:** Weekly interviews during active product development
- **Documentation:** All interviews transcribed and analyzed
- **Validation:** Problems confirmed by 3+ independent users

### Design Standards
- **Accessibility:** WCAG AA compliant (AA is minimum)
- **Consistency:** All designs follow design system
- **Iterations:** Minimum 2 design iterations before dev
- **Handoff:** Design specs complete before engineering starts
- **Documentation:** Design decisions documented with rationale

### Analytics Standards
- **Metrics:** All features have 3+ success metrics
- **Tracking:** Events implemented at launch
- **Review cycle:** Weekly metric reviews during first month
- **A/B testing:** 80% statistical power before declaring winner
- **Retention:** Track 30-day, 60-day, and 90-day retention

### Roadmap Standards
- **Visibility:** 12-month roadmap available
- **Granularity:** Quarterly goals > monthly features > weekly tasks
- **Dependencies:** All cross-functional dependencies mapped
- **Dates:** Confidence level disclosed (high/medium/low)
- **Updates:** Roadmap updated weekly, reviewed monthly
